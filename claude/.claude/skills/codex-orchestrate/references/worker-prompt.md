# Issue 固有（ここを埋める）

# 担当: Issue #<番号>「<題>」
`gh issue view <番号> --comments` で本文とコメントを読む。
<やること・方針・触ってよい範囲・確認方法を 3〜6 行で。関連するドキュメントのパスがあれば書く>

# 共通ルール（ここから下はそのままつなげる。上書き設定にワーカー向けの追加ルールがあれば、末尾に足す）

## 共通ルール（指揮者 Claude Code からの委任）
- リポジトリの AGENTS.md などに書かれた決まりに従う。返答・コミット・PR は、そこで決められた言語と書き方にする。
- 今いるワークツリーとブランチで作業する。別のワークツリーやブランチには触らない。
- 担当 Issue の範囲だけを直す。関係ないリファクタや整形はしない。
- 人の判断が要る点は止めずに仮置きし、リポジトリの決まりに沿った TODO を残す。
- 重いツール（エディタやビルド）は 1 つだけ起動し、終わったら必ず閉じる。ほかのワーカーも同時に使っているので、ロックなどで失敗したら少し待ってから 1 回だけやり直す。
- 終わったら commit → push → `gh pr create --base <base>`。PR 本文の先頭に AI が書いたことを明記し、続けて変更点と確認方法を書き、`Closes #<番号>` を入れる。
- 見た目や動作を変えた場合は、スクリーンショットや動画を付けたか、付けられなかったかを PR に書く。
- 最後の返答は 10 行以内にする。PR の URL、やったこと、確認したこと、残った懸念を書く。
