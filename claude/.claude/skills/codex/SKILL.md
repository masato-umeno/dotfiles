# Codex

Codex は別系統モデルの独立したエージェント。価値は「別の視点」であって「人手の追加」ではない。
文脈ゼロから始まり、ユーザーの ChatGPT プランの枠を消費し、通常数分かかる。
得られる洞察がそのコストに見合うときだけ呼ぶ。

## まず判断する

次のいずれかに当てはまれば Codex を使う:

- ユーザーが Codex や別モデルの意見を求めている。
- 自明でない、またはリスクのある変更が完成していて、自分のサブエージェントとは共有しない死角を独立レビューで拾える見込みがある。
- 設計判断に実質的なトレードオフがあり、推奨を出す前に反対意見を聞きたい。
- デバッグが行き詰まり、試行を重ねても新しい手がかりが増えない。

次の場合は自分で処理するか、自分のサブエージェントを使う:

- 小さい、機械的、またはやることが明確なタスク。
- この会話の文脈、ブラウザ、Artifact など自分にしかないツールが必要。
- 広いコード探索や並列調査。`Explore` や `general-purpose` サブエージェントの方が適する。
- 安いモデルで済ませたいだけ。それなら自分のサブエージェントのモデルを切り替える。

秘密情報、`.env` の内容、認証情報は Codex に渡さない。
ユーザーが Codex を指定したのに使わない場合は理由を伝える。

## 実行する

自己完結したプロンプトを書く: 目的、関連ファイルのパス、制約、試したこと、欲しい出力の形。
ユーザーが実装を明示的に任せない限り、Codex は読み取り専用で動かす。

```sh
codex exec -s read-only --ephemeral -C <repo> -o <scratchpad>/codex.md "<prompt>"
```

現在のリポジトリのコードレビュー:

```sh
codex exec review --uncommitted --ephemeral
codex exec review --base main --ephemeral
```

バックグラウンドで実行し、ポーリングせず完了通知を待つ。
10 分程度以上かかりそうなら `caffeinate -dis` で包む。
自分が編集中の作業ツリーに Codex を書き込ませない。変更を任せる場合は `--worktree` を使う。

## 結果を使う

Codex の出力は助言であり正解ではない。主張をコードで検証し、妥当なものだけ採用する。
どの指摘が Codex 由来か、どこで意見が異なるかをユーザーに伝える。
