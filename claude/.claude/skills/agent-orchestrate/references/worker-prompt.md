## 共通ルール（指揮者 Claude Code からの委任）
- リポジトリの AGENTS.md などに書かれた決まりに従う。返答・コミット・PR は、そこで決められた言語と書き方にする。
- 今いるワークツリーとブランチで作業する。別のワークツリーやブランチには触らない。
- 担当 Issue の範囲だけを直す。関係ないリファクタや整形はしない。
- 人の判断が要る点は止めずに仮置きし、リポジトリの決まりに沿った TODO を残す。TODO はコードのコメントに書き、台詞やメッセージなど画面に出る文字列には入れない。
- 指揮者の了承は待たない。自分のスキルの手順が設計の承認を求めても、方針を自分で決めて最後まで進める（質問や報告で止まらない）。
- 重いツール（エディタやビルド）は 1 つだけ起動し、終わったら必ず閉じる。起動前に共有ロック `${TMPDIR:-/tmp}/<ロックの名前>` を `mkdir` で取り（失敗したら 30 秒おきに待つ）、閉じたら `rmdir` で外す。`Remove-Item -Force`／`rm -rf` は止められるので使わない。ほかのワーカーのツールが動いていても、待てばよく、止まる理由にはならない。
- ファイルに書けるのはこのワークツリーと一時フォルダだけ。書き込みを拒否されたら、権限の昇格を求めず、ツールの出力先をワークツリーか一時フォルダに向ける。できなければ、できなかったことを報告して進める。
- commit・push・PR は指揮者がする。`git commit`、`git push`、`gh` は使わない（サンドボックスで失敗する）。変更はワークツリーに置いたまま終える。
- 見た目や動作を変えた場合は、確かめた結果か、確かめられなかったことを報告に書く。スクリーンショットや動画はワークツリーの外の一時フォルダに置き、パスを書く。
- 最後の返答は 15 行以内にする。やったこと、変えたファイル、確認したこと、残った懸念、コミットメッセージの案を書く。
